## Intent

草崩し（https://kusakuzushi.toshi0607.com/）を X で宣伝するための短尺プロモ。
GitHub の contribution graph が、そのままブロック崩しの盤面になる Web ゲーム。

コンセプトはユーザーが選んだ 2 案の混成:

- **掴みは素の草**（A案）: 1 コマ目は見慣れた GitHub の contribution graph。
  0.5 秒で「あ、俺の GitHub だ」と分かること。ここで自分ごとになる。
- **主役はカウンター**（B案）: 3,089 contributions の数字が画面を占め、
  ブロックが崩れるたびに減っていく。0 に落ちるまでが動画の背骨。

X はミュート自動再生で 1 秒目に止められる。だから「大きな数字が減っていく」という
言語も文脈も要らない絵で掴み、それが**自分の 1 年分**だと後から効かせる二段構造にする。

トーンは DESIGN-VISUAL.md の「夜の畑のアーケード」。破壊のカタルシスであって、
成果を否定する自虐ではない。

## Assets

- assets/play-full.mp4 — **主素材**。@toshi0607 の本物の草（3,060）を autopilot に自動プレイさせた
  実プレイ録画。ダークテーマ固定。まだ存在せず、`tools/` に録画ハーネスを組んで生成する
  （apps/web/src/attract.ts の autopilot ロジック + packages/core の Game/render を、
  デモグリッドではなく本物のグリッドに対して回し、chrome-headless-shell で撮って ffmpeg で結合）。
  全フレームがこの 1 本から時間指定で切り出される。
- ../../DESIGN-VISUAL.md — 草崩しのビジュアルデザイン仕様。ブランド真実として使う。
  パレット（`--soil` `#0C110D` / `--marquee` `#FFB224` ほか）、書体（DotGothic16 +
  IBM Plex Sans JP）、禁止事項まで定義済み。
- ../../DESIGN.md — プロダクトの設計書。ゲームの仕組みと用語の出典。

## Customizations

- **実プレイのキャプチャを主素材にする**。モーショングラフィックスで盤面を再現するのではなく、
  実際に動いているゲームを撮って使う。ユーザーの明示的な要望。
- **キャプチャはダークモード**（「夜の畑」`#0C110D`）で撮る。X のダークモード利用者比率と、
  暗い地のほうが草の緑とアンバーのボールが立つため。
  録画ハーネスでは core の `DARK_THEME` の `colors[0]` を `#0C110D` に差し替えている。
  この値は level 0 のセル色であると同時に canvas 全面の地色でもあり（renderer.ts）、
  GitHub 準拠の `#161b22` のままだと映像が動画の地に貼られた明るい矩形として浮いて、
  盤面が出る全フレームに継ぎ目が見える。失うのは「contribution 0 の日の箱」だけで、
  この 1 年は 365 日中ほぼ全日が level 1 以上のため実害がない。
- **崩し始めにグリッドへズームイン**。1 年分の草は 53 列あり、1:1 に収めると 1 マスが潰れる。
  序盤の「素の草」は横長のまま上下に余白を取って見せ、崩れる瞬間は寄って 1 マスを読ませる。
- **カウンターは実プレイの当たり判定に同期**させる。ブロックに当たった瞬間に数字がガクッと落ちる。
- **完全に無音**（ナレーション・BGM・効果音すべてなし）。当初は効果音のみ入れる方針だったが、
  効果音は HeyGen カタログからの取得が前提で未サインインのため、ユーザーが無音を選択。
  X のフィードはミュート自動再生なので実害は小さい。無音で成立する設計にする。

## Notes

- **装飾エフェクトは全面禁止**。スキャンライン、CRT 湾曲、グロー等。
  DESIGN-VISUAL.md が明示的に禁じている（「ピクセルはコンテンツに実在するので、
  フィルタで演出する必要がない」）。
- **緑は草だけのもの**。UI アクセントはマーキーアンバー `#FFB224` 一色。
  スコア・カウンター・CTA に緑を使わない。これは仕様の最重要ルール。
- **読ませる数字は実在の値だけ**。画面で読めるのは Frame 1 の `3,089` と Frame 4 の `0` の両端で、
  どちらも録画時点の実データ（@toshi0607 の直近 1 年 = 365 ブロック / 3,089 contributions）。
  Frame 2 の最初の落下（3,089 → 3,085）も実際にそのブロックが持っていた値。
  それ以降の中間値は読み取れない速さで回る演出値で、実データのカーブとは一致しない
  — 読めない以上、正確さより「減っている」という運動の連続性を優先している。
- 数字は日々変動する。録画し直したら Frame 1 / 2 の値も録り直した実測に合わせること
  （`tools/rebuild-clips.sh` が録画と切り出しを再現し、`assets/play-full.stats.json` に
  フレームごとの実測値が残る）。
- Chrome 拡張版はまだストア未公開。動画で拡張版を訴求しない。
- 着地は `kusakuzushi.toshi0607.com`。
