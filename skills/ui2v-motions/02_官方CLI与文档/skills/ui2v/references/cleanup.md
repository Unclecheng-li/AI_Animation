# UI2V cleanup guide

Use this when asked to clean, audit, simplify, or de-legacy the UI2V repository.

## Current active surface

Keep and maintain:

- `packages/ui2v` — active npm package `@ui2v/cli`, binary `ui2v`
- `skills/ui2v` — Codex skill for registry workflows and project positioning
- `docs/quick-start*`, `docs/getting-started*`, `docs/architecture*`,
  `docs/roadmap*`, `docs/npm-publish.md`, `docs/legacy-json-toolchain*`
- `scripts/bump-version.mjs`
- `.github/workflows/publish-npm.yml`
- root `ui2v-logo.svg` as the lightweight official README logo

## Legacy patterns to remove or avoid

- `examples/` containing old `animation.json` renderer demos
- renderer smoke scripts such as `smoke-render`, `smoke-preview`, `smoke-validate`
- references to `packages/cli`, `packages/core`, `packages/runtime-core`,
  `packages/engine`, or `packages/producer` as current code
- commands such as `ui2v doctor`, `ui2v validate`, `ui2v preview`, `ui2v render`
- README galleries or showcase assets generated by the removed renderer stack

## Before deleting

- Search for references with `rg`.
- Confirm root `package.json` and `.github/workflows` do not call the target.
- Prefer `git rm` for tracked files.
- Run `bun run test`, `bun run build`, and `git diff --check`.

## Keep as migration context

Legacy information should live in `docs/legacy-json-toolchain.md` and
`docs/legacy-json-toolchain.zh.md`, not scattered across the README or active
workflow docs.

Compatibility naming notes should live in `docs/naming-migration.md` and
`docs/naming-migration.zh.md`.
